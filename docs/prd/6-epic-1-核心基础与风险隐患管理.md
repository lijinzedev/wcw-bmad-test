# 6. Epic 1: 核心基础与风险/隐患管理

**史诗目标:** 搭建系统基础框架和权限体系，上线风险录入和隐患排查闭环管理的核心功能，并支持移动端上报。这是整个平台的MVP（最小可行产品）核心。

### Story 1.1: 项目初始化与核心框架搭建

- **As a** 开发团队,
- **I want** 初始化项目结构、数据库和核心服务框架,
- **so that** 我有一个稳固的基础来开始构建业务功能。

**验收标准:**

1. 根据技术假设（Monorepo, 微服务），后端和前端的代码仓库结构已创建。
2. 数据库连接已配置成功，并创建了初始的用户和权限相关的表结构。
3. 后端服务（如Java Spring Boot）已搭建，并包含一个可正常访问的健康检查API端点。
4. 前端应用（如Vue.js）已初始化，能够运行并显示一个占位页面。
5. CI/CD（持续集成/持续部署）流水线已初步建立，能够自动化构建和部署到开发环境。

### Story 1.2: 基础用户与权限管理

- **As a** 系统管理员,
- **I want** 管理不同层级（矿、公司、集团）的用户账户和角色权限,
- **so that** 系统能够识别不同用户并控制其访问范围。

**验收标准:**

1. 管理员可以通过界面创建、编辑、禁用不同层级的用户。
2. 管理员可以创建角色（如：一线员工、矿级管理员），并为角色分配预设的权限。
3. 用户可以使用用户名和密码登录系统。
4. 系统能根据用户角色，在后端强制执行API访问控制。
5. 用户登录后，前端界面能根据其权限动态显示或隐藏菜单/按钮。

### Story 1.3: 风险清单管理

- **As a** 矿级安全管理员,
- **I want** 在PC端系统性地录入、编辑和查询安全风险点,
- **so that** 我可以建立并维护全矿的电子化安全风险清单。

**验收标准:**

1. 用户可以按照专业、区域、岗位等维度创建新的风险点。
2. 创建风险点时，可以填写风险描述、事故类型、风险等级、责任单位/人和管控措施等字段。
3. 所有已录入的风险点以列表形式展示，并支持按条件筛选和关键词搜索。
4. 用户可以导出完整的风险清单为Excel文件。

### Story 1.4: 移动端隐患快速上报

- **As a** 一线员工,
- **I want** 通过手机App快速上报现场发现的隐患,
- **so that** 信息能够第一时间进入系统，提升上报效率和准确性。

**验收标准:**

1. 用户可以通过手机App登录系统。
2. 上报页面设计简洁，必填项少。
3. 用户可以拍摄或上传照片/视频作为隐患证据。
4. 用户可以进行文字描述，并支持语音输入转文字。
5. 提交成功后，用户在App内能看到自己的上报记录及处理状态。

### Story 1.5: 隐患闭环管理（PC端）

- **As a** 矿级安全管理员,
- **I want** 在PC端对上报的隐患进行指派、跟踪、审核与验收,
- **so that** 我能确保每一条隐患都得到有效闭环。

**验收标准:**

1. 管理员可以在PC端的看板或列表中看到所有待处理的隐患。
2. 管理员可以将隐患指派给具体的整改责任人/单位。
3. 整改人可以提交整改报告和相关证据。
4. 指定的验收人可以对整改结果进行“通过”或“驳回”的操作。
5. 隐患的状态（待指派、整改中、待验收、已关闭）在全流程中清晰可见。
6. 系统能自动记录每个流程节点的时间和操作人，形成完整的台账。
