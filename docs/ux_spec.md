## 1. 简介 (Introduction)

本文件定义了“煤矿双预防系统”的用户体验（UX）目标、信息架构（IA）、核心用户流程和视觉设计（UI）规范。它旨在确保产品为所有层级的用户——从一线员工到集团决策者——提供一个清晰、高效、可靠且一致的使用体验。

### 1.1 总体用户体验目标与原则

#### 目标用户画像 (Target User Personas)

- **一线员工 (Frontline Worker):**
  - **目标:** 在光线不佳、网络不稳定的井下环境中，以最快速度、最少操作上报安全隐患。
  - **特征:** 技术熟练度不一，注重实用性和效率，使用移动设备。
- **矿级安全管理员 (Mine Safety Manager):**
  - **目标:** 高效处理和分派海量隐患信息，跟踪整改进度，确保每一个问题都形成闭环。
  - **特征:** 任务驱动，需要清晰的待办列表和流程看板，主要使用PC端。
- **公司/集团级管理者 (Corporate/Group Manager):**
  - **目标:** 快速掌握下属单位的整体安全态势，通过数据对比发现宏观问题和管理趋势。
  - **特征:** 结果导向，需要高度可视化的数据驾驶舱和分析报告，使用PC端和大屏。
- **政府监管员 (Government Regulator):**
  - **目标:** 便捷地查阅其监管范围内矿井的安全数据，并在线记录执法情况，重点跟踪督办事项。
  - **特征:** 关注合规性和重大风险，需要独立的、清晰的数据视图，使用PC端。

#### 可用性目标 (Usability Goals)

- **易学性:** 一线员工首次使用移动App，应在60秒内完成一次完整的隐患上报。
- **效率:** 矿级管理员处理一条隐患的分派、审核或验收操作，平均点击次数应少于5次。
- **满意度:** 在用户调研中，80%以上的管理者认为数据驾驶舱能够有效帮助他们做出决策。

#### 设计原则 (Design Principles)

1. **清晰至上 (Clarity Above All):** 界面信息层级分明，语言明确，杜绝歧义，让用户总能清晰地知道自己在哪，能做什么。
2. **效率为先 (Efficiency in Every Click):** 简化高频操作路径，为专业用户提供快捷方式，减少不必要步骤，让任务处理如行云流水。
3. **移动为基 (Mobile-First for the Frontline):** 移动端的设计必须绝对优先满足一线员工在恶劣环境下的使用需求——大按钮、高对比度、支持离线操作。
4. **数据驱动洞察 (Data-Driven Insights):** 不仅是展示数据，更要通过智能的可视化设计，帮助管理者发现问题、洞察趋势。
5. **一致性体验 (Consistency Across Levels):** 无论是哪个层级的用户，在哪个终端上操作，产品的核心交互模式和视觉元素都应保持一致，降低学习成本。

#### 导航结构 (Navigation Structure)

- **主导航 (Primary Navigation):** PC端采用左侧垂直导航栏，结构清晰，可折叠。导航项根据用户角色动态显示。
- **次级导航 (Secondary Navigation):** 在复杂模块内部，使用顶部标签页（Tabs）或面包屑（Breadcrumbs）来组织内容，明确用户当前位置。
- **移动端导航:** 采用底部标签栏（Bottom Tab Bar）作为核心功能的入口，如“上报”、“任务”、“我的”。

## 3. 核心用户流程 (User Flows)

#### 流程1: 一线员工移动端快速上报隐患 (Story 1.4)

- **用户目标:** 尽快将现场发现的隐患问题提交到系统中。
- **入口:** App主界面的“上报隐患”巨大按钮。
- **成功标准:** 从点击“上报”到提交成功，平均时长不超过60秒。

```
sequenceDiagram
    participant User as 一线员工
    participant App as 移动App
    participant Server as 后端服务器

    User->>App: 点击“上报隐患”按钮
    App->>User: 显示上报表单（大字体、高对比度）
    User->>App: 填写描述 (支持语音输入)
    User->>App: 拍照或上传视频/照片
    App-->>Server: (后台) 压缩图片/视频
    User->>App: 选择隐患级别（可选，默认为一般）
    User->>App: 点击“提交”
    App->>Server: 发送隐患数据
    Note over App: 支持离线缓存，网络恢复后自动上传
    Server-->>App: 返回成功回执
    App->>User: 显示“提交成功”提示
```

#### 流程2: 矿级管理员PC端处理隐患 (Story 1.5)

- **用户目标:** 对新上报的隐患进行审核、指派，并最终验收关闭，形成闭环。
- **入口:** PC端主页的“待处理隐患”看板。
- **成功标准:** 管理员可以一站式完成所有处理流程，状态流转清晰。


## 4. 品牌与风格指南 (Branding & Style Guide)

#### 视觉识别 (Visual Identity)

- 严格遵循**山能集团**的企业VI规范，但在色彩应用和布局上进行现代化诠释，使其更适合数字化产品。
- **风格:** 专业、严谨、清晰、可信赖。避免不必要的装饰，功能性优先。

#### 色彩规范 (Color Palette)

- **主色 (Primary):** `#005A9C` (山能蓝) - 用于顶栏、主按钮、关键链接和选中状态，代表专业与稳定。
- **辅色 (Secondary):** `#F0F2F5` (淡灰) - 用于页面背景，提供舒适的阅读体验。
- **点缀色 (Accent):** `#FFB800` (安全黄) - 用于提示、警告和需要用户关注的元素。
- **状态色:**
  - **成功 (Success):** `#28A745` (绿色) - 用于成功提示、已完成状态。
  - **警告 (Warning):** `#FFC107` (黄色) - 用于警告信息、待处理任务。
  - **危险/错误 (Error):** `#DC3545` (红色) - 用于错误提示、高危风险、超期未整改的隐患。

#### 字体排印 (Typography)

- **字体:** Source Han Sans (思源黑体) / Inter - 现代无衬线字体，确保在各种屏幕尺寸和分辨率下都清晰易读。
- **字号体系:**
  - H1 / 页面标题: 24px Bold
  - H2 / 模块标题: 20px Bold
  - H3 / 卡片标题: 18px Medium
  - 正文 (Body): 14px Regular
  - 辅助文字 (Caption): 12px Regular

#### 图标 (Iconography)

- 采用一套风格统一、表意明确的线性图标库（如 Lucide Icons）。图标设计应简洁明了，避免复杂和产生歧义的图形。
