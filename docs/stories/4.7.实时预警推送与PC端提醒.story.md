# Story 4.7: 实时预警推送与PC端提醒

## Status
DONE

## Story
As 管理端与值班员,
I want PC 端能够实时收到新的预警/指派/升级事件提醒（无需轮询）, 
so that 提升响应速度并减少服务器与客户端负载。

## Acceptance Criteria
1. 后端提供实时推送通道（SSE 或 WebSocket，优先 SSE）：
   - 事件类型至少包括：NEW_ALERT、ASSIGNED、ACK_CHANGED、ESCALATED、SLA_REMIND。
   - 仅向有权限的用户推送与其相关的事件，遵循 4A。
2. 前端PC在任意受保护页面建立单一连接，显示角标/Toast/声音提示（可配置开关），可点击跳转到对应页面（预警看板或详情）。
3. 网络异常可自动重连；断开期间的消息不要求补发（可在列表中拉取）。
4. 提供开关与最简降级：关闭时前端回退到现有 API 拉取，不影响使用。

## Dev Notes
### Design Choices
- 首选 SSE：实现简单、浏览器支持良好、便于按用户建立通道；如需跨域/反向代理，确保 Nginx 支持 `proxy_set_header Connection ''` 与缓存关闭。
- 权限过滤：在服务端按用户ID与角色决定是否发送；避免在客户端筛除导致信息泄露风险。
- 可观测性：记录订阅数、活跃连接数与近 1 分钟事件数；告警阈值用于容量规划。

### API Specifications（拟）
- `GET /api/v1/monitoring/stream` → `text/event-stream`，事件字段：`event`、`data(JSON)`、`id`、`retry`

### File Locations
- 后端：`controller/MonitoringStreamController`、在 `MonitoringService/NotificationManagerService/SlaEvaluationService` 触发事件钩子
- 前端：`src/services/eventStream.js`、在 `main.js` 或 `store` 初始化订阅；更新 Admin 菜单角标与 `/alerts`

### Testing Requirements
- 前端：模拟 EventSource 事件触发与UI更新；后端：鉴权订阅、事件发送接口基本用例

### Technical Constraints
- 4A：仅推送与用户相关事件；连接空闲心跳；断线重连指数退避
