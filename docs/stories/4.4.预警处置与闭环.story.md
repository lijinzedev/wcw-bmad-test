# Story 4.4: 预警处置与闭环

## Status
Ready for Review

## Story
**As a** 安全管理员/值班员,
**I want** 在系统内对监控预警进行确认、指派与处置并可一键升级为隐患，
**so that** 预警能快速转化为可跟踪的整改事项并形成闭环管理。

## Acceptance Criteria
1. 管理员可在“预警看板”按时间/级别/地点/是否确认筛选预警，并查看详情原始载荷与阈值命中信息。
2. 预警支持确认/取消确认（ACK/UNACK），记录确认人与时间，且具备幂等处理与审计日志。
3. 预警可指派处理人（单人或角色），记录指派人、指派时间与备注；仅拥有权限的角色可指派。
4. 预警可一键升级为“隐患”，自动带出指标、地点、描述与严重级别，建立双向关联（预警→隐患），并跳转到隐患详情。
5. 所有操作符合 4A 要求：鉴权校验、行为审计、敏感信息脱敏展示；同时提供 MockMvc/单元测试覆盖主要路径与异常分支。

## Dev Notes
### Context
- 4.2/4.3 已提供预警采集、阈值与通知联动；当前需求聚焦“处置闭环”。

### Design
- 幂等：ACK/UNACK 基于当前状态短路；重复 ACK 返回 200 + 当前状态，不报错。
- 并发：可选添加字段版本或最后更新时间比对；首次实现允许简单的“最后写入”策略，后续再优化为乐观锁。
- 升级：创建隐患时复用预警的 `metricCode/metricName/location/severity/message` 构造描述，责任单位取当前管理员所在组织或预设映射。
- 可观测性：关键操作写审计；对外接口返回统一错误结构与分页头。

### API Specifications（拟）
- `PATCH /api/v1/monitoring/alerts/{id}/ack` body: `{ acknowledged: boolean, note?: string }`
- `POST /api/v1/monitoring/alerts/{id}/assign` body: `{ assigneeId?: UUID, assigneeName?: string, notes?: string }`
- `POST /api/v1/monitoring/alerts/{id}/escalate` → `{ hazardId: UUID }`

### File Locations
- 后端：`controller/MonitoringController` 扩展；新增 `service/AlertWorkflowService`；`model/MonitoringAlert` 字段扩展与迁移脚本；必要时 `repository` 扩展查询。
- 前端：新增 `views/monitoring/AlertsBoardView.vue`、扩展 `services/monitoring.js` 与可选 `stores/alertsStore.js`；更新路由与 Admin 导航。

### Testing Requirements
- 后端：MockMvc 覆盖 ACK/指派/升级成功与失败路径；服务层单测覆盖幂等与权限拒绝。
- 前端：Vitest 覆盖筛选、按钮交互、接口错误提示与路由守卫。

### Technical Constraints
- 严格 4A：仅管理员或相应职能角色可操作；敏感字段（手机号等）前端脱敏显示。
- 事务性：升级为隐患与预警回填需事务包裹，失败回滚。
