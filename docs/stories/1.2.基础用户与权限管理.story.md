# Story 1.2: 基础用户与权限管理

## Status
Done

## Story
**As a** 系统管理员,
**I want** 管理不同层级（矿、公司、集团）的用户账户和角色权限,
**so that** 系统能够识别不同用户并控制其访问范围。

## Acceptance Criteria
1. 管理员可以通过界面创建、编辑、禁用不同层级的用户。
2. 管理员可以创建角色（如：一线员工、矿级管理员），并为角色分配预设的权限。
3. 用户可以使用用户名和密码登录系统。
4. 系统能根据用户角色，在后端强制执行API访问控制。
5. 用户登录后，前端界面能根据其权限动态显示或隐藏菜单/按钮。

## Testing
### 后端
- 认证：
  - 成功登录返回200与JWT；错误凭据返回401（不泄露细节）。
  - 持JWT访问受保护端点成功；无JWT或无权限时返回401/403。
- 授权：
  - 仅管理员角色可访问用户/角色管理接口；普通用户被拒绝。
- 数据：
  - `isEnabled=false`用户无法登录；角色变更立即影响授权决策。
 - 边界情形（如适用，架构未明确，需在实现中说明处理或暂不实现理由）：
   - 连续失败登录的锁定策略（未在架构中定义）。
   - 密码复杂度/过期策略（未在架构中定义）。
   - Token过期后的行为与刷新策略（未在架构中定义）。

### 前端（PC）
- 登录页：
  - 表单校验与错误提示；成功登录后持久化token并导航到主界面。
- 权限驱动UI：
  - 菜单/按钮按角色显示/隐藏；直接访问受限路由被重定向。
