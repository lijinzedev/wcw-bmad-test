# Story 4.6: 移动端预警推送与反馈

## Status
DONE

## Story
As 一线责任人,
I want 在移动端及时收到本人相关的预警并能进行确认/反馈,
so that 预警能在现场快速处置并及时回传状态。

## Acceptance Criteria
1. 责任人在移动端可查看“我的预警”列表，支持筛选（未确认/已确认、严重级别、时间）与详情查看。
2. 责任人在移动端可对本人相关预警执行“确认/取消确认”，系统记录时间与操作者并写审计日志。
3. 支持最简方式的移动端提醒：当产生与该责任人相关的预警或指派时，系统向其发送 PUSH（占位）或通过移动端轮询 API 实时显示未确认条数。
4. 移动端无权查看他人预警；接口与页面遵循 4A 鉴权与统一错误结构。

## Dev Notes
### Scope & Constraints
- 本故事不实现真实 Push 通知通道，采用占位与轮询方式保证最小可用提醒；后续可替换为企业 IM 或 APNs/FCM 集成。
- 与“指派规则/权限”对齐：仅被指派或规则明确指定的责任人才可见/可操作。

### API Specifications（拟）
- `GET /api/v1/monitoring/my-alerts?acknowledged=&severity=&from=&to=&page=&size=` → 分页 + 头 `X-Total-Count`/`X-Total-Pages`
- `GET /api/v1/monitoring/my-alerts/count` → `{ count: number }`

### File Locations
- 后端：`MonitoringController` 扩展 my-alerts 查询与 count；复用 `ack` 接口鉴权校验
- 移动端：`pages/alerts/*`, `services/monitoring.js`, 导航入口

### Testing Requirements
- 后端：MockMvc 覆盖 my-alerts 仅本人可见、分页与过滤、ACK 权限拒绝
- 移动端：页面加载/筛选/ACK 交互与轮询更新
